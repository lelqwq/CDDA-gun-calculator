# gunlab — Cataclysm-DDA 枪械数学模型

不启动游戏，搜索枪械、装配件、横向对比。所有公式逐条复刻自 Cataclysm-DDA
源码，代码注释里标了出处（`文件:行号`）。

**图形界面**（SDL3 + ImGui），`scripts\build_gui.bat` 一键构建。
**数据规模**：332 把枪 / 730 种弹药 / 170 个配件，由脚本从游戏数据生成。
（游戏数据里带 `GUN` 子类型但其实不是枪械的条目已滤掉 —— 弓弩投石索、
已废弃条目、怪物攻击模板等，共 69 条。详见 `CLAUDE.md`。）

---

## 功能

左边是枪械列表（可按名称 / 技能 / 重量排序，可按技能筛选），
顶部搜索框匹配**中文名 / 英文名 / id / 变体别名**。选中一把枪后右侧展开：

- **已装配件 + 安装配件** —— 只列**这把枪能装**的配件并按槽位分组，
  一个槽位只能装一件，装新的自动替换。改装后所有数值实时重算
- **瞄准参数** —— 体积因子、长度因子、瞄准精度上限、总散布、每发增加的瞄准误差
- **游戏内显示值** —— 与游戏物品面板一致的数值，附作用说明：
  散布 / 瞄准散布 / 实际后坐 / 理论最小后坐力
- **瞄准等级** —— 三个档位各自的「50%命中距离」与「瞄准用时」
- **瞄准时间线** —— 瞄准误差随回合下降的曲线，三条橙色横线是档位阈值
- **瞄准收益与连射** —— 横轴瞄准回合、纵轴 50% 好击距离的多条曲线；
  连发模式下另有逐发明细表（每发的误差、距离、好击及以上概率）。
  弹药推不动枪机循环时还会给出卡壳警告
- **瞄准档位实例** —— 四个瞄准程度各自的误差、固定散布、总散布、50%命中距离
- **误差与命中档位** —— 横轴瞄准误差、纵轴各命中档位的概率，距离可调。
  「暴击」给的是**过了额外判定后的真实比例**。基于 `dispersion_sources::roll()`
  的掷骰模型做蒙特卡洛采样，固定随机种子所以结果可复现

人物参数（敏捷 / 感知 / 力量 / 武器技能 / 枪械技能）在顶部可调，改动会立刻重算全部数值。

### 搜索

匹配**中文名 / 英文名 / id / 变体别名**，大小写不敏感。所以 `glock`、`格洛克`、
`glock_29`、`Glock 29 pistol` 都能命中同一把枪。

### 怎么验证数据准不准

**gunlab 里的"游戏散布"列，就是游戏物品界面上 `Dispersion:` 显示的数字。**
单枪详情里还有一整块「游戏内显示值」，列出散布 / 瞄准散布 / 实际后坐 / 理论最小后坐。

验证方法：在游戏里随便找一把枪看它的数值，在 gunlab 里搜同一把枪，**数字应该完全一致**。

⚠️ **注意 gunlab 内部有两个刻度，别拿错了去比：**

| | 例子（Glock 20 + 10mm 被甲弹） | 用途 |
|---|---:|---|
| 游戏界面显示 | **5.30 MOA** | 和游戏对照用 |
| gunlab 的"枪散布" | **29** | 参与射击公式的是这个（= 原始值 ÷ 18） |
| gunlab 的"枪基础散布(原始)" | 180 | JSON 里的原值 |

游戏界面里的枪械数值一律是**内部值 ÷ 100**（`item_info.cpp:1252` 等），
而且散布**不除以** `GUN_DISPERSION_DIVIDER`。所以 5.30 和 29 都是对的，只是刻度不同。

### 游戏内各项数值的作用

游戏物品面板上「散布 / 瞄准散布 / 实际后坐 / 理论最小后坐力」这四项是枪械手感的核心。
gunlab 的单枪详情会原样复现这四个数字。

| 面板上的项 | 是什么 | 对玩法的影响 |
|---|---|---|
| **散布** | 子弹的**抖动角度**（枪身散布 + 弹药散布） | **决定命中档位**。这个值不变，但偏离目标的距离**随射程线性放大**——1 格时几乎无差别，20 格外就很明显。散布越大，同一距离下越容易从「好击」掉到「擦伤」（伤害只剩 5%~25%） |
| **瞄准散布** | 瞄准能压到的**误差下限**（瞄具散布 + 感知视差） | **瞄得再久，散布也不会低于它**。这就是「精度天花板」。感知越低视差越大，天花板越高（越不准）。换好瞄具主要就是在降这个值 |
| **实际后坐** | 每开一枪给瞄准误差**增加的数值** | 开火后瞄准误差按 `5 × 该值 × (1 − 技能吸收)` 上涨，技能最多吸收一半。**误差涨上去只能靠重新瞄准压回来**——这是枪战的主要时间成本。注意近战/移动/换弹会把瞄准误差**直接打回满值** |
| **理论最小后坐力** | 力量补足到「所需力量」后能达到的后坐 | 与「实际后坐」对比即可判断力量够不够：**相等 = 力量已够**；实际更大 = 力量不足，后坐被放大了 |

游戏面板上其余几项：

| 项 | 作用 |
|---|---|
| **远程伤害** | `枪身修正 + 弹药伤害`。**伤害主要来自弹药**；枪管越长伤害越高（弹药有一张按枪管长度插值的伤害表） |
| **穿甲** | 同上，`枪身 + 弹药`。决定子弹能穿透多厚的护甲，对重甲目标影响很大 |
| **最大射程** | 子弹能飞多远（格）。**超出的目标无法瞄准**，不是"精度变差"而是"打不到" |
| **枪管长度** | 同时影响**伤害**和**散布**（通过弹药的 `dispersion_modifier` 插值表）。模块化枪械的枪管长度由上机匣提供 |
| **暴击加成** | 命中时的暴击倍率 |
| **装填耗时** | 换一次弹消耗的行动点（1 回合 = 100 行动点） |
| **射击噪声** | 开枪的噪音大小，决定吸引多少僵尸。受弹药类型和枪口配件影响 |
| **技能** | 这把枪吃哪个技能等级。**技能同时影响散布惩罚、瞄准速度和后坐吸收**，是收益最高的投资 |

### 模块化枪械

M4A1 这类枪的枪身只是"下机匣"——口径、重量、体积、枪管长度都由上机匣提供。
装上一个上机匣后：

- 配件列表立刻多出 **弹壳收集器 / 刺刀座 / 导轨 / 瞄具 / 管下 / 枪口** 六组槽位
- 重量体积变成 3148 g / 3310 ml（= 880+2268 / 1760+1550）
- 弹药列表按新口径过滤

## 编译

**双击 `scripts\build_gui.bat`**，产物 `build-gui\gunlab_gui.exe`。

手工做的话（脚本就是这三步）：

```powershell
cmake -B build-gui -S . -G "MinGW Makefiles" `
      -DCMAKE_PREFIX_PATH=C:/msys64/mingw64 -DCMAKE_BUILD_TYPE=Release
cmake --build build-gui
powershell -File scripts\copy_gui_deps.ps1 -Exe build-gui\gunlab_gui.exe -Dest build-gui
```

> **第 3 步别漏**：`cmake` 的 `-static` 只管我们自己编的 exe，
> SDL3.dll 后面还拖着 `libiconv-2.dll` 这类 msys64 的运行库。
> 不拷的话双击会因为找不到 DLL 直接退出。

**只能用 MinGW**：本机唯一的 SDL3 是 msys64 的 MinGW 版，MSVC 链不了它。

## 目录结构

代码分三层：**数据层**（生成 + 容器）、**计算层**（纯函数）、**界面层**。
`gunlab_core` 静态库打包前两层，不含任何输入输出。

```
gunlab/
├── CMakeLists.txt
├── README.md / CLAUDE.md
├── .gitignore / .gitattributes
├── src/
│   ├── gun_data.h                 结构体 + 常量 + 接口          ┐
│   ├── gun_data.cpp               容器 + 填充函数              │ gunlab_core
│   ├── gunlab_math.h/.cpp     ★   全部公式（纯函数，无 IO）     │ 静态库
│   ├── zh_cn.h                    全部中文文本                 │
│   └── generated/                 自动生成，勿手工编辑          ┘
│       ├── gen_guns.cpp           332 把枪
│       ├── gen_ammo.cpp           730 种弹药
│       └── gen_gunmods.cpp        170 个配件
│   └── gui/main_gui.cpp           图形界面（SDL3 + ImGui）
├── third_party/imgui/             从游戏源码里拷来的 ImGui
├── scripts/
│   ├── gen_gun_data.py            ★ 数据生成器
│   ├── stats_guns.py              看一眼生成的数据（技能分布 / 连发数…）
│   ├── build_gui.bat              一键构建
│   ├── copy_gui_deps.ps1          把 MinGW 运行库拷到 exe 旁边
│   ├── screenshot_gui.ps1         启动 + 截图（改界面时用来自查）
│   ├── extract_zh.py              查任意字符串的官方译名
│   └── lookup_zh.py
└── build-gui/                     构建产物（可整个删掉）
```

## 更新数据

游戏更新后重新生成：

```bash
python scripts/gen_gun_data.py --game "C:\Users\34068\Project\Cataclysm\CDDA"
```

加 mod：

```bash
python scripts/gen_gun_data.py --game "<路径>" --mods Aftershock,Xedra_Evolved
```

然后 `git diff` 就能看出游戏更新带来了哪些数值变化——这本身也是个有用的能力。

### 生成器做什么

1. 读 `data/json` 下全部 JSON（按类别加 mod）
2. 解析 `copy-from` 继承链，含 `proportional` / `relative`（递归到嵌套对象）
3. 从游戏的 `.mo` 翻译文件里查官方中文名
4. 输出 `src/generated/` 下三个 C++ 文件

### 生成器的几个关键规则

**变体的正式名**：若某变体的 `id` 等于条目 id，它就是这把枪的正式名，
条目自身的 `name` 反而是通用称呼（如 `glock_20` 的 "Glock pistol"）。

**别名合并**：变体不作为独立条目，而是挂成父条目的别名。220 个变体里 189 个
数值与父条目完全相同，只有 31 个有几十克的重量差——独立成条只会让对比表刷屏。

**同名条目过滤**：`data/json/ascii_art/ammo/10mm.json` 里有个
`{"type":"ascii_art","id":"10mm_fmj"}` 的字符画条目，按字母序排在 `items/`
之前。不过滤的话会用它覆盖真条目，导致弹药数值全为 0。

**中文名**：查 `.mo`，有就用，没有就保留英文原名。实测覆盖率 97.1%，
未译的 2.9% 全是 `Glock 36` / `S&W 460XVR` 这类本就该保留原文的型号名。

> 踩过的坑：Python 的 `gettext` 把部分条目存成**元组键** `('bipod', 0)` 而不是
> 字符串，必须同时试 `C.get(s)` 和 `C.get((s, 0))`，否则一条都查不到。

## 已知取舍

1. **`extend` / `delete` 有意跳过**。它们只操作 `effects` / `flags` 这类数组
   （弹药里 extend 动 effects 235 次、delete 动 flags 186 次），gunlab 不使用
   这些字段。若要新增依赖它们的列，需在生成器里补上。
2. **变体的重量微差被丢弃**（31 个变体，几十克量级），对散布/后坐/瞄准速度无影响。
3. **`damage.barrels` 枪管长度插值表不存储** —— 当前对比表不含伤害列。
4. **弹药只取 `recoil` / `dispersion` / `range`**，其余字段不生成。
5. **7 把枪在游戏数据里没有 `dispersion` 字段**（按 C++ 默认值 0 处理）：
   `TDI_10` / `bio_emp_gun` / `combination_gun` / `mut_longpull` /
   `ruger_lcr_22` / `takedown_recurbow_folded` / `usp_45`。
   生成时会在终端提示。这是游戏数据本身的情况，不是解析错误。
6. **公式层面的简化**：`ranged_dex_mod()` 用 `(DEX−8)×1.0` 近似（游戏里是
   `character_modifier` 表驱动）；手部操作惩罚按"健康"处理；激光瞄具的光照
   条件按"白天"处理；命中档位按目标体积 1.0 计算。

## 中文文本

界面文字全在 `src/zh_cn.h`。译名取自游戏本体的
`lang/mo/zh_CN/LC_MESSAGES/cataclysm-dda.mo`，用 `scripts/extract_zh.py` 提取。

`GunMod.location`（`"underbarrel"`）、`Gun.skill`（`"rifle"`）、`GunMod.id`
是**逻辑键**，代码里有 `has_mod("underbarrel")`、`g.skill == "archery"` 这类比较，
且与游戏 JSON 字段对应，**不要翻译**——但它们不会出现在输出里。
